# Ops Runtime Requirements

## Application Servers

- Main API server: `server/`, NestJS GraphQL and Socket.IO, production port provided by `PORT`, local default `1002`.
- RAG server: `rag-server/`, FastAPI rulebook QA API, consumed by main server through `RAG_SERVER_URL`.
- VAD server: `silero-vad/`, FastAPI Silero voice activity detection API, consumed by main server through `VAD_SERVER_URL`, local default `1003`.

The Expo web client is built as static files and deployed to S3 plus CloudFront, so it is hosting infrastructure rather than a long-running application server. The native iOS and Android clients are distributed through EAS/App Store/Play Store and call the main API server.

## Managed Data And Infra

- MySQL is declared through Prisma via `DATABASE_URL`, but the current `server/src/app.module.ts` has `PrismaModule` commented out, so it is not active in the current runtime graph.
- RAG chat history uses DynamoDB through `DDB_TABLE_FOR_RAG`.
- RAG vector data is generated by `rag-vector-db-generator/`, uploaded to S3, then copied into the RAG server package.
- Static web hosting uses S3 bucket `teacher-bo-client` and CloudFront distribution `E2HHRGQCO89EBY`.
- Transcribe vocabulary sync uploads `infra/transcribe/vocabulary-filter.txt` to S3 and updates an Amazon Transcribe vocabulary filter.

## Runtime External Keys

- `OPENAI_API_KEY`: used by `rag-server` LangChain `ChatOpenAI` for GPT-4o-mini answers.
- `UPSTAGE_API_KEY`: used by `rag-server` and vector generation for Upstage Solar embeddings; also used by rulebook OCR when generating vector DB from PDFs.
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`: used by the main server for Amazon Transcribe Streaming and Amazon Polly.
- `DDB_AWS_ACCESS_KEY`, `DDB_AWS_SECRET_ACCESS_KEY`, `DDB_AWS_REGION`, `DDB_TABLE_FOR_RAG`: used by the RAG server for DynamoDB-backed session history.

## Runtime Environment Values

- Main server: `PORT`, `NODE_ENV`, `CLIENT_URL`, `RAG_SERVER_URL`, `VAD_SERVER_URL`, `JWT_SECRET`, `JWT_EXPIRES_IN`, and currently documented `DATABASE_URL`.
- Client: `EXPO_PUBLIC_URL`, `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_CLIENT_PORT`, `EXPO_PUBLIC_API_PORT`, `EXPO_PUBLIC_DEV_LOCAL_IP`.
- RAG server: optional LangSmith tracing values `LANGCHAIN_TRACING_V2`, `LANGCHAIN_ENDPOINT`, `LANGCHAIN_API_KEY`, `LANGCHAIN_PROJECT`.

## Deployment Secrets

- Shared AWS deployment secrets currently used by workflows: `RAG_AWS_ACCESS_KEY_ID`, `RAG_AWS_SECRET_ACCESS_KEY`, `RAG_S3_BUCKET`, `RAG_EB_APPLICATION_NAME`.
- Main server deployment: `MAIN_SERVER_ENV`, `MAIN_SERVER_EB_ENVIRONMENT_NAME`.
- VAD deployment: `VAD_SERVER_ENV`, `VAD_SERVER_EB_ENVIRONMENT_NAME`.
- RAG deployment workflow exists but is disabled with `if: ${{ false }}`; if re-enabled it needs `RAG_ENV`, `RAG_EB_ENVIRONMENT_NAME`, and vector DB S3 secrets.
- Vector DB generation: `VECTOR_DB_GEN_ENV`, `VECTOR_DB_GEN_AWS_ACCESS_KEY_ID`, `VECTOR_DB_GEN_AWS_SECRET_ACCESS_KEY`, `VECTOR_DB_GEN_AWS_REGION`, `VECTOR_DB_GEN_S3_BUCKET_NAME`.
- Transcribe vocabulary sync: `STT_AWS_ACCESS_KEY_ID`, `STT_AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `TRANSCRIBE_S3_BUCKET`, `TRANSCRIBE_VOCABULARY_FILTER_NAME`.
- Client web deployment: `CLIENT_ENV`; S3 bucket and CloudFront distribution are hard-coded in `.github/workflows/deploy-client.yml`.
