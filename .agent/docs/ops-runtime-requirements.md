# Ops Runtime Requirements

## Application Servers

- Main API server: `server/`, NestJS GraphQL and Socket.IO, container name `teacher-bo-server`, host port `8095`, internal port `8095`.
- RAG server: `rag-server/`, FastAPI rulebook QA API, container name `teacher-bo-rag`, internal port `8096`.
- VAD server: reused from the production `NLP-Biblabely` deployment as `biblabely-vad:8094`.

The Expo web client remains a static S3 plus CloudFront deployment and is not part of the Docker backend deployment.

## Runtime Topology

- `teacher-bo-server` and `teacher-bo-rag` join `biblabely_network`.
- `teacher-bo-rag` and global `redis` join `redis_network`.
- Only `teacher-bo-server` publishes a host port: `8095:8095`.
- `teacher-bo-server` calls `RAG_SERVER_URL=http://teacher-bo-rag:8096`.
- `teacher-bo-server` calls `VAD_SERVER_URL=http://biblabely-vad:8094`.

## Managed Data And Infra

- RAG chat history uses Redis TTL keys under `teacher-bo:rag:history:{session_id}`.
- Redis is a global Docker container named `redis`, backed by `/opt/redis/data`, with AOF enabled, `256mb` max memory, and `allkeys-lru`.
- Redis is not exposed through a host port; backend containers access it through `redis_network`.
- RAG vector data is generated by `rag-vector-db-generator/` and baked into the `teacher-bo-rag` Docker image as `chroma_db`.
- MySQL is still documented through Prisma via `DATABASE_URL`, but `server/src/app.module.ts` does not activate `PrismaModule`, so MySQL is not part of the current production runtime graph.

## Runtime External Keys

- `OPENAI_API_KEY`: used by `rag-server` LangChain `ChatOpenAI` for GPT-4o-mini answers.
- `UPSTAGE_API_KEY`: used by `rag-server` and vector generation for Upstage Solar embeddings.
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`: used by the main server for Amazon Transcribe Streaming and Amazon Polly.
- `REDIS_PASSWORD`: used by deployment to create/access global Redis and by `teacher-bo-rag` for session history.
- Optional LangSmith values: `LANGCHAIN_TRACING_V2`, `LANGCHAIN_ENDPOINT`, `LANGCHAIN_API_KEY`, `LANGCHAIN_PROJECT`.

## Deployment

- Backend deployment is handled by `.github/workflows/deploy-backend.yml`.
- Reusable build workflows are `.github/workflows/build-server.yml` and `.github/workflows/build-rag.yml`.
- Backend images are pushed to ECR repositories `teacher-bo-server` and `teacher-bo-rag` with the commit SHA tag.
- Deployment uses SSH secrets `SERVER_HOST`, `SERVER_USERNAME`, `SERVER_PASSWORD`, and `SSH_PRIVATE_KEY`, matching the `NLP-Biblabely` server deploy pattern.
- AWS/ECR and app runtime secrets use `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `OPENAI_API_KEY`, `UPSTAGE_API_KEY`, `REDIS_PASSWORD`, and optional `JWT_SECRET`.
- Legacy Elastic Beanstalk workflows for main server, RAG server, VAD server, vector DB S3 upload, and Bedrock KB RAG sync were removed from the active workflow set.
